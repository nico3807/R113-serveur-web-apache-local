7. Sécuriser un dossier (authentification)

Mise en place d'une « Basic Authentication » sur le dossier /admin.

  1. Créez le dossier /var/www/html/admin avec une page index.html.
  2. Autorisez le AllowOverride All dans apache2.conf (bloc <Directory /var/www/>).
  3. Créez le fichier .htaccess dans /admin.
  4. Générez le fichier de mots de passe avec htpasswd.
  5. Rechargez (ou redémarrez) Apache pour qu'il relise apache2.conf.
  6. Ouvrez .../admin/ dans le navigateur : une fenêtre de connexion apparaît.
  7. Connectez-vous avec le login et le mot de passe choisis.
Indice : syntaxe .htaccess 
AuthType Basic
AuthName "Zone Admin"
AuthUserFile /etc/apache2/.htpasswd
Require valid-user

La commande pour créer l'utilisateur : htpasswd -c /etc/apache2/.htpasswd [login].

Indice : trouver AllowOverride dans apache2.conf

nano /etc/apache2/apache2.conf, puis descendez avec les flèches jusqu'au bloc <Directory /var/www/> et remplacez None par All sur la ligne AllowOverride de ce bloc (pas celui de <Directory /> !). Dans un navigateur, n'utilisez pas Ctrl + W pour chercher : ce raccourci ferme l'onglet.

8. Personnalisation des erreurs (UX)

Soignons l'expérience utilisateur en remplaçant la page 404 austère.

  1. Créez /var/www/html/oups.html avec un design MMI.
  2. Configurez-la dans /etc/apache2/sites-available/000-default.conf.
  3. Rechargez Apache.
  4. Testez avec une URL inexistante.
Indice : directive ErrorDocument

Ajoutez cette ligne dans le bloc <VirtualHost *:80> :

ErrorDocument 404 /oups.html

Observer les échanges

Le navigateur envoie une requête HTTP, le serveur renvoie une réponse avec un code de statut et des en-têtes. Les outils de développement les affichent dans l'onglet Réseau.

  1. Ouvrez l'onglet Réseau (bouton 🛠 Réseau du navigateur d'entraînement).
  2. Chargez une adresse inexistante : la requête en échec 404 apparaît en rouge.
  3. Cliquez sur une requête réussie (200) pour lire ses en-têtes : User-Agent et Content-Type.

Dans votre vrai navigateur (Windows) : F12 ou Ctrl + Maj + I, onglet Réseau, puis rechargez la page (F5).

Dans votre vrai navigateur (macOS) : ⌘ + ⌥ + I, onglet Réseau, puis rechargez la page (⌘ + R).

Mini-jeu : quel code de statut ?

Pour chaque situation rencontrée dans ce TP, quel code de statut Apache renvoie-t-il ?

La page existe et Apache a le droit de la lire.
On demande /test (sans « / » final), qui est un dossier.
Le dossier /admin demande un identifiant et un mot de passe.
www-data n'a pas le droit de traverser /home/etudiant.
L'adresse demandée ne correspond à aucun fichier.
Le .htaccess contient une directive mal orthographiée.

À retenir

Après chaque modification d'un fichier .conf, vérifiez la syntaxe (apache2ctl configtest), puis rechargez le service (systemctl reload apache2) : sans cela, Apache garde l'ancienne configuration. Un fichier .htaccess, lui, est relu à chaque requête, à condition que AllowOverride l'autorise.
